## 一、设计理念

### 1. 名字就是画面

"弦光"两个字本身就是设计方案：一根弦，发光。所以画面正中横着一根弦，它就是产品的名字，也是画面里唯一的视觉符号。不做和名字无关的装饰——这也是上一版（v3）的问题：那版的角标、内框、镂空数字、开关、音量柱，每一项单看都成立，合起来却是一套可以套在任何产品上的通用黑金模板，跟"弦光"没有关系。

### 2. 一个焦点，其余全部退让

整幅画面只有两个亮的东西：**弦**，和**被按下的琴键**。标题、参数、琴键音名都用暖灰，明度刻意压低。观众第一眼看弦，第二眼看琴键，不需要第三眼。

判断标准：如果一个元素去掉之后画面没有变差，它就不该存在。v3 到 v4 删掉的东西比增加的多，这是刻意的。

### 3. 金色是贵金属

金色（`#d8bd86`）只出现在三个地方：弦、和弦音名、按下的琴键。其余全部是暖灰的四个明度层。金色一旦铺开——标签是金色、数字是金色、键帽是金色——它就不再值钱，画面也就失去了贵气。稀缺性是高级感最便宜的来源。

### 4. 层次来自排版，不来自装饰

不用分割框、不用色块、不用阴影卡片来区分区块，而是用**字号差**和**字距差**：

- 主角"柔和钢琴"58px 极细宋体
- 参数值 38px Bodoni 数字
- 标签 10.5px，字距 .28em
- 英文小字 9.5px，字距 .42em

字号从 58 到 9.5 跨了六倍，主次自然分明。字号差距拉大，装饰就可以全部删掉。

### 5. 用物理真实代替电子特效

振动特效做两版，是这份设计里最重要的一次判断：

- **v5（弃用）**：正弦折线。线条尖锐、起伏均匀地铺满整条弦，整条线一起抖。这是示波器、频谱条、音乐播放器的视觉语言——是"电子特效"，不是"弦"。
- **v6（采用）**：**长曝光下的一根振动弦**。真实的琴弦振动，用长曝光拍出来是柔和的"光茧"：弦在振幅两端停留时间最长，所以光茧**边缘最亮、中间通透**。被拨动的位置是一个主光茧，两侧各有一个逐渐变小的光茧（驻波节点）。

高级感的来源不是更复杂的算法，而是**换一个参照物**：从"电子设备的显示"换成"摄影和乐器本身的物理"。凡是能用真实物理现象解释的效果，都比凭空设计的特效更耐看。

### 6. 因果链必须成立

光丝从弦上垂下来，落在对应的琴键上，琴键**顶端**被这道光照亮（暖色从键顶往下衰减）。这样"手指按下 → 琴键 → 弦 → 光"是一条完整的因果链，而不是两块各自发光的装饰。做界面时反复问：这个光是从哪来的？如果答不上来，就是特效不是设计。

### 7. 待机要安静

待机画面是那根**一动不动**的弦，中间一个很淡的光点，然后是"按下琴键，开始演奏"。不闪烁、不呼吸、不放待机动画。安静本身就是高级感——产品一直在那里等着，不需要证明自己醒着。

### 8. 像素级节制

- 线一律 1px，不加 2px 边框
- 圆角只用在琴键（3px）和状态点，标题、面板、边角全部直角
- 不用发光滤镜做大面积光晕，光只出现在弦和被按的键上
- 加一层极淡的胶片颗粒（6% 不透明度，overlay 混合），消除纯色渐变的数码感

这几条都是为了让画面在 800×480 这个尺寸下不显廉价：小屏上任何一处"厚"一点，整体都会塌。

## 六、振动弦的算法

### 6.1 模型

每个按下的音对应一段**驻波**。符号：

- `s`：该音距 C4 的半音数（C4 = 0 … B5 = 23）
- `x_n`：该音对应琴键的中心横坐标
- `j`：按下顺序（0 起），`order` 为同时按下的音数
- `x`：画布内横坐标，`Y = 35` 为弦的静止位置

```
半波长   h_n = 40 · 2^(−s/24)                      音越高，光茧越窄
振幅     A_n = 12.5 · (1 − s/42) · (0.86 + 0.14·(j+1)/order)
包络     u = (x − x_n) / h_n
         g_n(x) = exp(−u²)                        每个音的驻波只在自己附近
相位差   δ_n = 1.37 · j                            先按的音略微失相
位移     disp(x,φ) = Σ_n A_n · g_n(x) · [ cos(φ+δ_n)·cos(πu)
                                        + 0.2·cos(2φ+1.7δ_n)·cos(2πu+0.6) ]
边缘渐隐 disp'(x,φ) = disp(x,φ) · min(1, x/46, (704−x)/46)
```

第二项是弱的二次谐波，让光茧两端略微不对称，避免过于数学化。

### 6.2 绘制（长曝光）

关键在于**不画函数图像，而是叠画很多个相位**，让弦在振幅两端的停留时间自然累积成亮度：

```js
const K = 64;                                  // 相位数量
for (let k = 0; k < K; k++) {
  const φ = 2 * Math.PI * k / K;
  // 每条线：1px 宽，透明度 0.06，两端 46px 渐隐
  描线(x → Y + disp'(x, φ));
}
// 另加 16 条 2.2px 宽、blur(5px)、透明度 0.07 的粗线做柔光
// 另加 2 条沿 ±包络的 0.6px、透明度 0.22 的轮廓线，让光茧边缘清晰
```

透明度乘 K 之后总能量约等于一条实线的 4 倍，所以单条线必须很淡（0.06）。相位越多越顺滑，64 是个好平衡。

**叠加顺序**：先画柔光层，再画 64 条发丝线，最后画两条包络轮廓。混合模式用 `lighter`（加法）。

### 6.3 音符参数对照（示例：F 大七和弦）

| 音 | s | 键中心 x（画布内） | h | A |
| --- | --- | --- | --- | --- |
| F4 | 5 | 176.0 | 34.7 | 9.85 |
| A4 | 9 | 276.6 | 30.8 | 9.13 |
| C5 | 12 | 377.1 | 28.3 | 8.62 |
| E5 | 16 | 477.7 | 25.2 | 7.74 |

从表里能直接看出设计意图：**F4 是舒展的大结，E5 是紧致的小结**——光茧大小与音高一一对应，观众不看音名也能感受到音区。

### 6.4 落到 FPGA

`xianguang_v6.html` 是**参考实现和离线渲染器**（可以用它导出任意和弦的定稿图）。板载实现建议走下面两条路之一。

**方案 A：解析式逐像素计算（省内存，推荐）**

不需要帧缓冲。利用一个性质：**画面的振动区只有 704×70，而且同一列上包络 `E(x) = Σ A_n·g_n(x)` 相同**。所以：

1. 每列只算一次 `E(x)`（4 个音 × 一次 `g_n` 查表），存进一行列缓存
2. 逐像素只做：`d = |y − 35| × recip(E(x))`，再用 `d` 查一条 256 项的**相位密度曲线表** `p(d)`
3. `p(d)` 就是长曝光的密度分布——`d≈1`（包络边缘）最亮，`d≈0`（中轴）最暗。这张表在电脑上用 6.2 的 JS 跑一次导出即可

代价估算：每像素约 5～6 个操作加两次查表（倒数表 + 密度表），加 2～3 级流水线即可。比现在 `studio_scene.v` 里逐像素比较的复杂度只高一点。

其中 `g_n(x) = exp(−u²)` 建议换成 `cos²(πu/2)`（|u| < 1 时），视觉上几乎看不出差别，但只需要一次 `cos` 查表：

```
g_n(x) ≈ cos²(π·u/2),  |u| < 1
```

**方案 B：精灵图加法混合（最省算力）**

在电脑上用 6.2 的 JS 把 12 个音级的光茧各渲染成一张 96×64、4bpp 的精灵（每张 3KB，共 36KB），存进 BSRAM。板载只做：

1. 对每个按下的音，按 `x_n` 取对应精灵
2. 在 704×70 的振动区里累加（加法混合，饱和）
3. 边缘 46px 用现成的渐隐系数乘一次

每像素 4 次 BRAM 读 + 4 次加法。Tang Nano 20K 的 BSRAM 够用，但会吃掉相当一部分，需要你按现有资源权衡。

**不要做的**：直接用正弦函数画折线（v5 的做法）。它是"电子特效"的视觉语言，和"弦"无关；而且整条线一起抖，没有主次。

### 6.5 琴键被照亮

按下时不要整体提亮，而是**光从上方照下来**：

```css
.wk.on {
  background:
    radial-gradient(95% 52% at 50% 0%, rgba(238,198,128,.62), rgba(238,198,128,0) 100%),
    linear-gradient(180deg,#83765f 0%,#cfc0a2 9%,#e5d9c3 40%,#ebe2d0 88%,#d9cdb8 96%,#c0b39b 100%);
  box-shadow: 0 2px 0 rgba(226,184,108,.9) inset;   /* 键底一道金线 */
}
```

FPGA 上等价于：在琴键矩形内，按 `(键顶到当前行) / 键高` 查一条 16 项的暖色衰减表，再和键的底色做 1 次线性插值。黑键同理但幅度只有白键的一半左右（`.34` 对 `.62`）。
